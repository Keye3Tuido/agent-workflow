# MCP 协调服务验证记录

## 验证范围

正式代码位于 `scripts/coordination/`，测试位于项目 `tests/`。验证使用 A、B、C 三个独立身份，分别绑定 `session-a`、`session-b`、`session-c`，共享同一项目。所有状态、服务进程和依赖均在临时目录，不读取或修改真实 Agent 配置。

协议与生命周期测试使用官方 `mcp==2.3.0`、`PyYAML==6.0.3`、协议 `2026-07-28` 和仅绑定 `127.0.0.1` 的 Streamable HTTP。服务使用无状态模式和 JSON 响应；业务身份通过显式参数传递。

现有测试 87 项，加上协调核心 9 项、真实 MCP 6 项、单实例进程 2 项、服务管理 1 项、打包与模式隔离 1 项，共 **106 项全部通过**。

## 重复稳定性验证

- 正式协调核心：20 轮 × 9 项，共 **180 项次全部通过**。
- 正式真实 MCP、单实例和服务管理：10 轮 × 9 项，共 **90 项次全部通过**。
- 先前实验阶段的协调语义 400 项次、真实 MCP 100 项次、单实例 40 项次也已通过。
- 默认安装专项：在临时 HOME 与项目外状态目录中执行两次 `install_mcp.py`，首次为 `started`、第二次为 `existing`，实例 ID 不变，服务版本为 1.4.0；验证后已停止服务并清理环境。

验证过程中实际修复了裸 `dict` 无法生成严格 Schema、异步客户端跨任务退出、数据库重复建表、测试管道资源泄漏、PyYAML 依赖遗漏，以及任务清理后编号可能复用的问题。

## 复现命令

```bash
mkdir -p tmp
python3 -m venv tmp/mcp-venv
tmp/mcp-venv/bin/python -m pip install --disable-pip-version-check \
  -r lucid-workflow/scripts/coordination/requirements.txt
TMPDIR="$PWD/tmp" tmp/mcp-venv/bin/python -B -m unittest \
  discover -s tests -v
```

验证结束后删除临时依赖和状态：

```bash
rm -rf tmp
```

没有 MCP 依赖时，协调核心与既有测试仍运行，真实 MCP、单实例和服务管理测试会明确跳过，不会把跳过计为通过。

## 尚未验证，不能宣称完成

- 真实宿主注册、系统服务安装、宿主心跳、Agent 自动创建或唤醒；
- 其他 SDK、旧协议、第三方客户端和 stdio；
- 机器断电、磁盘故障或部分写入下的持久性；强制终止恢复不等于断电测试；
- 目录层级写入范围、路径规范化、worktree 和分支归属；
- 文本不同但语义相近的问题去重、问题阻塞调度；
- 审计事件的滚动保留与生产数据导入导出；
- 真实 Agent 是否遵守最少打扰、验收范围和调用时机；
- 身份认证、权限控制与恶意输入防护；
- 固定端口冲突、跨版本端点发现和真实宿主稳定 URL 解析。

本结果证明可选实现的协调语义、真实协议和单实例生命周期通过了当前测试，不等于批准真实 Agent 接入、生产迁移或发布。
