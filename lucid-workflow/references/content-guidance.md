# `info.yml` 内容摘写指南

`info.yml` 只保存导航和维护所需的目录职责、内容作用及重要文件说明。上下文定位由 `forest_context.py` 按需计算，不把依赖关系、源码摘录或检索索引写入 YAML。

## 事实依据

1. 以当前源码、配置、资源、入口和测试反映的行为为主。
2. 用调用方、被调用方和输入输出确认职责与协作关系。
3. 现有说明仅作辅助；与实现不一致时以实现为准。

不得凭名称或旧摘要猜测，也不得把计划写成现有能力。无法核验时写明缺口；结构校验通过不代表语义准确。

## 字段写法

| 字段 | 应写内容 | 避免 |
| --- | --- | --- |
| `purpose` | 当前目录的职责、服务对象或使用场景 | 重复目录名，如“存放脚本” |
| `contents_summary` | 当前层内容的整体作用，必要时补充主要输入输出或协作方向 | 展开下级结构，与 `purpose` 换词重复 |
| `files[].purpose` | 文件的具体职责，以及何时值得查阅 | “主程序”“工具文件”等空泛描述 |
| `files[].details` | 有助于维护的入口、数据契约、约束、副作用或权威来源 | 罗列所有元信息；没有内容时省略 |
| `boundary` | 目录或文件模块不负责的事项、调用约束 | 与 `purpose` 换词重复，罗列所有不负责事项 |
| `entry` | 理解模块时最有价值的主要入口 | 记录所有函数或行号 |
| `files[].core` | 仅在架构主编排类或稳定契约上写 `true`，查询时直接补充 | 为提高覆盖率把普通文件全部标为核心 |
| `depends_on` | 跨功能模块的直接依赖及架构目的 | 模块内部调用、反向或传递依赖、无原因的引用 |
| `directories[].name` | 纳入范围的直接子目录名称 | 在父级重复子目录的用途和内容概括 |
| `directories[].recurse` | 仅写 `false`，停止镜像后代 | 显式写默认的 `true` |

目录路径由文件位置推导，不单独保存。子目录的 `purpose` 和 `contents_summary` 只写在其自身 `info.yml` 中，需要时进入读取，不在父级重复。

文件按维护价值选择，入口、核心实现、配置、关键资源和测试优先；列出的文件必须存在。空 `files` 和 `directories` 省略。

## 精简边界

省略行号、逐行逻辑、函数或参数清单、具体常数、补丁式叙述、重复复述和制作摘要的流水账。

保留当前职责与边界、关键入口、输入输出、阶段契约、影响维护的配置与依赖、副作用、限制，以及必要的待核验缺口。只写当前状态，使用项目或用户要求的语言。

## 更新范围

1. 复核变化目录的 `info.yml`；新增或删除直接子目录时更新父级名称列表。
2. 职责、接口、数据契约或副作用变化时，同步受影响的相邻摘要。
3. 语义未变时不为制造更新而改写。

## 示例

```yaml
schema_version: "1.0"
purpose: "提供项目维护命令"
contents_summary: "接收项目路径和状态参数，产出检查报告、状态文件或宿主链接"
files:
  - name: "check_doc_forest.py"
    purpose: "核验目录镜像和信息文件并报告结构问题"
    details: "支持完整与局部检查；只读源项目"
directories:
  - name: "fixtures"
```
